# V1 trust boundaries

Browser: deterministic questionnaire and explicitly approved public artifact only. Consent is page-session-only; AI failure does not erase answers. Public ask accepts bounded/redacted context and current validated public configuration. It cannot choose a credential resolver, file path, admin tool or activation flag.

Hostinger PHP: trusted private configuration may construct an actual SeraPrivateProviderRuntime from private libraries. Vault uses existing authenticated encryption and independently supplied key interface; real writes/activation remain gated. Public bridge accepts that final runtime instance only. Application HMAC counters and durable per-provider ledger are separate. Quota unknowns are never refunded automatically. Request budget and output/context limits apply before provider calls.

Apps Script: Calendar booking source requires authoritative event readback before confirmation and invitations. Sheet-bound ControlCenter role/token checks govern private operational records. Sheet/script editors can bypass application roles; use a trusted-team container, never claim customer isolation. No browser-to-private PHP credential management bridge is deployed.

CMS: approved allowlisted content export → isolated validated media/staging → exact manifest → verified active/previous pointer. No arbitrary filesystem manager, protected-hero write or production publication is added. Hosted auth/media/runtime proof remains required.
